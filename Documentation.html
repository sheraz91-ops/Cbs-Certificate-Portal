How API calls work

JSON response envelope

Most routes return the standard envelope. Client helpers return the value inside Content.

{
  "Code": 200,
  "Content": {},
  "Count": 1,
  "Message": "Successfully completed",
  "Status": "Success"
}

Error responses

JSON errors use the same envelope with Status: "Error" and Content: { "error": "..." }. Check both the HTTP status and envelope status.

{
  "Code": 400,
  "Content": { "error": "Validation message" },
  "Count": 0,
  "Message": "Validation message",
  "Status": "Error"
}

Methods and credentials

Unless marked GET, a route uses POST with a JSON request body. Same-origin credentials are sent by the shared API client. Admin and organizer protected routes use their respective session cookies.

Reading the call-site column

Paths identify the page, component, or server helper where the request originates. A page may call a feature API wrapper rather than invoking fetch directly.

Implementation note: Payloads and returned data below are concise summaries. The route validation schemas and TypeScript types in the listed source files are authoritative if a field changes.

SOURCE OF TRUTH

Shared API clients and types

Client wrappers and shared helpers used by the route callers.

lib/api-client.ts

Shared getData and postData helpers, same-origin credentials, envelope parsing, and API errors.

lib/api-response.ts

Server-side successResponse and errorResponse JSON envelope helpers.

features/events/api.ts

Event listing, existing-account verification, registration, and event-detail requests.

features/certificates/api.ts features/certificates/organizer-api.ts

Public lookup and organizer certificate requests.

features/admin/api.ts features/organizers/api.ts

Admin console and organizer session/data requests.

features/users/api.ts features/users/registrationFormApi.ts

User management and public/admin registration-form requests.

features/workshops/api.ts features/participants/api.ts

Workshop and participant administration requests.

types/api.ts

Shared API envelope types. Route-specific request/response types are defined near their feature clients and validation schemas.
